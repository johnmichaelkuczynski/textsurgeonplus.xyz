THIS IS GOING TO A MASSIVE OVERHAUL. 
STEP 1: READ AND ABSORB THE UPLOADED DOCUMENTS, WHICH DESCRIBE HOW (IN DIFFERENT APPS OF MINE) THE ABILITY TO READ AND GENERATE LARGE COHERENT DOCUMENTS IS ACHIEVED. IT IS ACHIEVED MAINLY 
THROUGH THE PRELIMINARY OUTLINING THAT IS DESCRIBED AND ALSO THROUGH THE TRACTATUS TREE TECHNOLOGY THAT IS DESCRIBED. 
STEP 2: WHENEVER A TEXT IS UPLOADED, THE APP MUST BREAK DOWN INTO SECTIONS THAT ARE SMALL ENOUGH THAT ITS CURRENT FUNCTIONALITY WORKS ON THEM. 
STEP 3. THE APP MUST BE ABLE TO WORK ON ANY GIVEN ONE OF THESE SMALL CHUNKS; IT MUST BE ABLE TO PERFORM ALL ITS USUAL FUNCTIONS (PODCAST, OUTLINE, ETC.) 
STEP 4: IN ADDITION, A NEW FUNCTION WILL BE INTRODUCED: GENERATE "TRACTATUS TREE." EACH LITTLE CHUNK WILL HAVE THIS. 
STEP 5: WHEN MULTIPLE CHUNKS ARE INVOLVED--FOR EXAMPLE---IF THE USER SELECTS A SERIES OF PAGES THAT TAKE UP 10 CHUNKS---THE APP HAS TO USE A SPECIAL PROCEDURE. 
STEP 6. FIRST IT USES THE PROCEDURE DESCRIBED IN THE UPLOADED COHERENCE DOCUMENTS TO GENERATE A COHERENT SUMMARY OF IT, WHICH IT USES AS A MAP. BASICALLY, IT DOES WHATEVER THOSE DOCUMENTS SAY IT IS SUPPOSED TO DO. 
STEP 7: IT ALSO GENERATES A TRACTATUS TREE FOR THE WHOLE AREA SELECTED. THIS MAY INVOLVE GENERATING MULTIPLE TRACTATUS TREES AND THEN "SYNTHESIZING" THEM, TO OMIT IRRELEVANT DETAL AND TO INCLUDE KEY POINTS. IT MAY ALSO VERY LIKELY PRESUPPOSE THAT THE OTHER COHERENCE FUNCTION HAS BEEN RUN. 
STEP 8: ALL OF THE OTHER FUNCTIONS--PODCAST, TEST ME, OUTLINE, LITERATURE REVIEW--WILL BE RECONFIGURED SO THAT THEY ALIGN WITH THIS NEW FUNCTIONALITY. TO EXPLAIN: RIGHT NOW, IF THE USER WERE TO GENERATE A PODCAST OF A 90 PAGE SELECTION, IT WOULD NOT BE COHERENT, BECAUSE THE PODCAST GENERATOR HAVE TO TREAT THOSE 90 PAGES AS MULTIPLE SHORT INDEPENDENT PASSAGES. BUT WITH THIS NEW FUNCTIONALITY IN PLACE, IT WILL BE ABLE TO TREAT IT AS THE COHERENT ENTITY THAT IT IS. 
STEP 9: WHEN TEXTS ARE VERY SHORT (ORDER 0), THERE IS NO NEED FOR TRACTATUS TREES OR SPECIAL COHERENCE-RELATED MEASURES. WHEN THEY ARE ON ORDER OF MAGNITUDE BIGGER (ORDER 1), THEN ONE TRACTATUS TREE/ONE WHATEVER IS NECESSARY. (THE 'WHATEVER' REFERS TO THE OUTLINE THAT, TO MY DIM RECOLLLECTION, MY APPS--THE ONES THAT HAVE COHERENCE FUNCTINOALITY--MAKE IN ORDER TO GIVE THEMSELVES A MAP OF LARGE SWATHS OF TEXT SO TAHT THEY CAN TREAT THOSE SWATHS AS WHOLES, RATHER THAN AS MULTIPLE INDEPENDENT PIECES.) WHEN THEY ARE ORDER 2, THAT MEANS THAT COHERENCE AND EREWRITES ARE ACHIEVED INDIRECTLY: NOT BY DIRECTLY CRAWLING THROUGH TEXT BY GENERATING TRACTATUS TREES/SUMMARY-MAPS AND THEN SYNTHESIZING THOSE. ORDER 3: BY SYINTHESIZING ORDER 2 MAPS/TREES. ORDER N+1: BY SYINTHESIZING ORDER N MAPS/TREES. 
STEP 10: WHEN THE USER UPLOADS A HUGE DOCUMENT (E.G. 800 WORDS), IT IS GOING TO TAKE A VERY, VERY LONG TIME TO DO ALL THIS STUFF; IT IS HARD TO PERFORM DOCUMENT-LEVEL OPERATIONS ON LARGE DOCUMENTS, EVEN IF ALL THIS FUNCTIONALITY WORKS (WHICH IT WILL). THEREFORE, TWO THINGS. FIRST, AFTER THE USER UPLOADS SUCH A DOCUMENT, THE APP SHOULD TELL HIM THAT DOCUMENT LEVEL OPERATIONS TAKE TIME TO PROCESS AND THAT, UNLESS HE WANTS TO SIT THERE FOR AN AHOUR, MAYBE HE SHOULD FOCUS ON SOME SMALLER PART OF THE TEXT. SECOND, IF THE USER TRIES TO RUN A DOC LEVEL OPERATION ON A LARGE DOC (WHICH MANY WILL), HE SHOULD HAVE THE ABILITY TO EASILY ABORT THE PROCESS (SINCE THE APP WILL LIKELY CRASH OR HE WILL JUST GET BORED). FOURTH, WHEN THE APP IS PERFORMING A DOC LEVEL DOC OPERATION ON LARGE DOC, THERE SHOULD BE PERIODIC (AND RATHER FREQUENT) PROGRESS REPORTS. MOREOVER, OUTPUT SHOULD BE DEPOSITED IN RELATIVELY SMALL CHUNKS SO THAT THAT USER CAN TELL IF THE APP IS ON THE RIGHT TRACK. FIFTH, AND MOST IMPORTANTLY, THE APP SHOULD BE ABLE TO COMBINE LOCAL OPERATIONS INTO BOOK LEVEL ONES; I.E. SUPPOSE THAT THE USER UPLOADS AN 800 PAGE BOOK AND HE PROCESSES IT 50 PAGES AT A TIME (E.G. HE GENERATES SUMMARIES OF EACH OF THOSE OF SETS OF 50 PAGES); THE APP SHOULD BE ABLE ON THAT BASIS TO GENERATE A SUMMARY OF THE ENTIRE 800 PAGE BOOK; SAME MUTATIS MUTANDIS WITH TESTS, OUTLINES, TESTS, PODCASTS, REWRITES (VERY IMPORTANT...THE REWRITE FUNCTION IS A VERY IMPORTANT OF PART OF THE APP). ALSO, THE APP PROBABLY HANDLES TXT MORE EASILY THAN PDF CUZ OF SIZE, SO THE USER SHOULD BE TOLD THAT. VERY VERY IMPORTANTLY, THE USERS ABILITY TO ASK DOCUMENT LEVEL QUESTIONS ABOUT WHOLE DOCUMENTS MUST EMBODY THESE COHERENCE FUNCTINALITIES; THIS IS KEY.THAT IS ALMOST THE WHOLE POINT. LET US SAY, SOME LAWYER UPLOADS AN 800 DOCUMENT FROM THE SEC AND QUERIES THE APP ABOUT IT; THE ANSWERS THE APP GIVES HIM MUST REFLECT AN UNDERSTANDING OF THE DOCUMENT AS A WHOLE; THOSE ANSWERS MUST NOT TREAT THAT DOCUMENT AS 39 INDEPENDENT DOCUMENTS. 
STEP 10: MAKE SURE THAT THE WINDOW WHERE THIS CRAP IS HAPPENING CAN BE RESIZED, MINIMIZED, MOVED, MADE UNOBTRUSIVE. 
STEP 11: USING THIS COHERENCE FUNCTIONALITY, CREATE A FUNCTION THAT SEARCHES TEH DOCUMENT INTELLIGENTLY; E.G. THAT CAN FOLLOW A COMMAND SUCH AS "FIND ALL EXAMPLES IN THIS DOCUMENT OF VIOLATIONS OF CLAYTON ACT" OR WHATNOT. THIS SHOULD BE A NEW FUNCTION: THE "QUERY" FUNCTION; MOREOVER, THE USER SHOULD HAVE THE ABLITY TO OPERATE ON THE OUTPUTS OF SUCH QUERIES.E.G. SUPPOSE THE APP FINDS 74 VIOLATIONS OF CLAYTON ACT, THE USER CAN SAY: OK LIST TEHSE FROM MOST EGREGIOUS TO LEAST; OR FOR EACH ONE, IDENTIFY ITS SIGNIFICANCE IN THE STATE OF DELAWARE.
